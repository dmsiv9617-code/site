# Восстановление внешнего доступа к администрации

Это HTTP Basic-защита Nginx, отдельная от WordPress. Команда не отключает защиту и не меняет пользователя WordPress, его роли или базу.

В подтверждённой установке серверный файл `/srv/woodbase/secrets/staging.htpasswd` подключён к веб-контейнеру как `/run/secrets/staging.htpasswd:ro`. Логин внешней защиты — `woodbase-reviewer`. Для ручного восстановления оператор подключает именно этот существующий файл к временному служебному PHP-контейнеру как `/auth/staging.htpasswd:rw`, а отдельную закрытую папку резервных копий — как `/backup`.

1. Сделать отдельную копию файла с сохранением прав в `/backup` с правами папки 0700. Проверить совпадение `cmp`, не выводить содержимое или хеши паролей.
2. Скачать проверенную закреплённую версию `scripts/recover-basic-access.php` во временную папку и сверить SHA-256.
3. Выполнить `php /tmp/wb-basic-reset.php /backup/проверенная-копия.bak` в интерактивной консоли TTY. Скрипт дважды запрашивает новый пароль со скрытым вводом, без аргументов командной строки и переменных окружения. Рекомендуется 20–30 латинских символов; допускается 16–72 байта.
4. Скрипт требует совпадения исходника и копии, ровно одну запись указанного пользователя и сохраняет остальные записи. Смена выполняется с блокировкой и проверкой записи. Существующий inode, владелец, группа и права сохраняются: замена файла через rename оставила бы работающий контейнер со старым bind-файлом.
5. После успеха проверить вход браузером под `woodbase-reviewer` с новым паролем. Следующий экран WordPress использует отдельную учётную запись. После восстановления снять временный доступ служебного контейнера к файлу защиты и убрать служебный контейнер, сохранив резервные копии в закрытом хранилище.

Скрипт доступен только как CLI, не является HTTP-endpoint и не выводит пароль или его хеш. Если скрытый ввод/TTY недоступен, операция прекращается. При отмене ввода и необычном состоянии терминала восстановить его командой `stty echo` или переподключить консоль.

Проверка: `python3 scripts/verify-basic-access.py`. Используются только изолированные тестовые файлы и локальный Nginx: проверяются bcrypt, отказ старого пароля, сохранение HTTP 401 без авторизации, работа обновлённого файла через уже подключённый read-only bind, неизменность прав/остальных пользователей и отказ при устаревшей копии. VPS и настоящие учётные данные тест не использует.
