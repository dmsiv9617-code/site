# Telegram-бот WoodBase: подключение

Бот владельца: **@WoodBaseLazerBot**, https://t.me/WoodBaseLazerBot. Прямой контакт мастерской @WoodBase_Lazer сохраняется отдельно.

Статус: код подготовлен; токен, webhook и закрытая группа на VPS не подключались. Реальные сообщения тестами не отправляются. По AGENTS.md серверный пакет требует отдельной проверки и ручной установки; одобренный fingerprint здесь не менялся.

## Что делает бот

1. Сайт сохраняет гостевой заказ в WooCommerce. При включённом боте API добавляет закрытую ссылку `https://t.me/WoodBaseLazerBot?start=wb_…`. Код случайный, не содержит номера заказа, контактов или рисунков. Новый неиспользованный код действует 48 часов.
2. Покупатель нажимает «Начать». Бот показывает сохранённые сервером позиции, надписи и сумму и предлагает «Отправить заказ мастерской». Первый открывший ссылку личный чат привязывается к заказу; другой чат не получает его данные.
3. Только после подтверждения заказ и Telegram-контакт поступают в закрытую группу сотрудников. Статус «Ожидает сообщения покупателя» меняется на «Нужно связаться с покупателем».
4. Дальнейший текст покупателя передаётся в группу с номером заказа. Сотрудник отвечает через функцию Telegram «Ответить» на сообщение бота в этой группе — бот доставляет текст привязанному покупателю. Ответ вне конкретного сообщения не пересылается.
5. Открытие другого подтверждённого заказа через его ссылку выбирает его для дальнейших сообщений покупателя. Номер указан в подтверждении. Открытие ещё не подтверждённого заказа приостанавливает пересылку до его подтверждения.

Первый выпуск передаёт **текст**, не документы, фото, голосовые сообщения и не оплату. Оригинал рисунка из конструктора уже хранится в заказе и доступен сотрудникам через защищённую администрацию, в Telegram публично не выгружается. Для нового рисунка покупатель использует сайт или прямой контакт мастерской.

Повторы одного update не обрабатываются 24 часа; повтор подтверждения не создаёт новый заказ и штатно не повторяет уведомление группы. При сетевом обрыве после фактической доставки Telegram сообщение может повториться: распределённая доставка не даёт гарантии «ровно один раз». Везде указан один и тот же номер заказа.

## Действия владельца

- Создать **закрытую группу**, например «WoodBase — заказы», добавить только сотрудников и @WoodBaseLazerBot. Бот должен иметь возможность отправлять сообщения. Полные права администратора не требуются.
- Сохранить токен BotFather в защищённых настройках окружения VPS, не в чате, Git или публичных VITE-переменных.
- Получить ID группы: до регистрации webhook отправить в группе `/setup@WoodBaseLazerBot`, затем оператор запускает `python3 scripts/configure-telegram-webhook.py --discover-groups`. Скрипт выводит только ID и названия групп, не токен и не текст сообщений. Если webhook уже установлен, скрипт его не отключает.

## Настройки сервера

Защищённое окружение PHP должно содержать:

| Переменная | Значение |
| --- | --- |
| `WOODBASE_TELEGRAM_BOT_TOKEN` | Секрет BotFather |
| `WOODBASE_TELEGRAM_WEBHOOK_SECRET` | Отдельная случайная строка 32–256 символов A–Z, a–z, 0–9, `_`, `-` |
| `WOODBASE_TELEGRAM_GROUP_ID` | Отрицательный ID закрытой группы |
| `WOODBASE_TELEGRAM_BOT_ENABLED` | `1` после проверки установки |

Переменные должны быть доступны именно процессам PHP-FPM; одного файла `.env` рядом с репозиторием недостаточно. Настройки серверного контейнера/FPM оператор меняет отдельно после проверки, не заменяя базу и private volume.

Установить согласованный комплект плагина, включая `telegram-order-bot.php`, и витрину с поддержкой `kind: bot`. Не направлять покупателей в бота до подключения обработчика. При отсутствующих/невалидных настройках бот выключен, используется прежний прямой контакт Telegram.

Оператор с тем же защищённым окружением запускает `python3 scripts/configure-telegram-webhook.py`. Скрипт проверяет имя бота, тип группы и членство бота, затем регистрирует HTTPS webhook с секретным заголовком, не сбрасывая очередь. Это внешнее изменение, выполняемое вручную после проверки серверной установки. Скрипт не отправляет сообщения пользователям.

Путь webhook: `/wp-json/woodbase/v1/telegram/webhook`. Он проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`; nonce покупателя здесь не используется. Ответы не кэшируются. Если WordPress ограничивает исходящие HTTP-запросы, разрешить `api.telegram.org` в существующем allowlist, сохранив остальные ограничения.

Не логировать токен, полный Telegram API URL с токеном, тело сообщений и start-ссылки в системах диагностики.

После настройки проверить отдельный тестовый заказ: старт, подтверждение, получение сотрудниками, ответ сотрудника, текст покупателя, повтор подтверждения и недоступность заказа из другого чата. Проверить обработку персональных данных и срок хранения переписки в принятой политике продавца.

Отключение `WOODBASE_TELEGRAM_BOT_ENABLED` возвращает прямой Telegram-контакт в оформлении; существующие заказы и файлы сохраняются. Для старых ссылок покупателей нужно заранее предусмотреть обслуживание и уведомление, не отключать рабочий бот без плана.

## Проверки кода

`npm test`, сборка WooCommerce и `python3 scripts/verify-telegram-bot-server.py`. Последняя запускается только в локальном Compose: WooCommerce/HPOS настоящие, все запросы Telegram заменены имитацией. Проверяются секрет webhook, непрогнозируемый код, срок действия, подтверждение, повторы, изоляция чатов и текст в обе стороны.

## Проверка на рабочем сервере 20 ноября 2026

Оператор вручную установил плагин 0.3.1 из коммита `35c040babf77d2b7a0ca67af29a6ec7c6b7cac1e`, предварительно проверив резервную копию, исходные файлы версии 0.2.0, SHA-256 всех шести новых файлов и PHP-синтаксис. Публичный `/product` подтвердил шесть товаров и цены дополнений 350/120/295/120 ₽. Публикация новой витрины и включение нового оформления ещё не подтверждены.

Подключение Telegram API не выполнено: в служебном и WordPress-контейнерах получен таймаут cURL 28 по IPv4. В сравнительной проверке WordPress github.com вернул HTTP 200 (TCP 0.179 s, TLS 0.284 s), api.telegram.org — HTTP 0, TCP/TLS 0.000 и таймаут через 8 s. DNS вернул 149.154.166.110. Причина ограничения/маршрутизации не установлена; это не подтверждение неправильного токена. Пользователь выбрал продолжение запуска через прямой Telegram-контакт без бота. Секретный токен в конфигурацию рабочего бота не устанавливался.

Для входа в администрацию отдельно восстанавливается HTTP Basic-доступ; см. [процедуру восстановления](basic-access-recovery.md). Пароль WordPress — отдельный уровень доступа.
