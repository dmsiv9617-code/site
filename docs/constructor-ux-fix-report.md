# WoodBase — исправления мобильного конструктора и восстановления проекта

6 ноября 2026, Europe/Moscow. Новая локальная ветка: **feature/woodbase-constructor-ux**. База: опубликованная и проверенная `feature/woocommerce-hardening`, **c28c4f1b6c3ef428e0b35b2928eee74ffe4ffd26**. Fetch всех удалённых веток не выявил опубликованного продолжения этой базы. WooCommerce/hardening сохранены; серверные PHP, инфраструктура, изображения альбомов, Вуди и фирменная графика не изменены.

Предыдущий аудит `docs/woodbase-site-audit.md` и его скриншоты до начала работ были незакоммиченными. Они сохранены как основание исправлений и включаются в локальный коммит вместе с этим отчётом. Исторические выводы аудита относятся к базе c28c4f1; этот документ описывает исправленные V1/V2 и связанные требования к безопасному восстановлению изображений.

## Воспроизведение до исправления

Перед изменением кода запущен `WB_UX_PHASE=before node scripts/verify-constructor-ux.mjs`:

- На **320 / 375 / 390 px** проверка hit-test падала: центр вкладок y≈298–345 попадал в DIV/IMG превью. На 768/1440 вкладки уже работали.
- В demo и live после настройки и reload проверка надписи падала: вместо «Мой незавершённый альбом» возвращалась «История нашей семьи».
- Отдельно воспроизведено завершение уже отменённого decode: выбрать файл → сбросить проект до завершения `createImageBitmap` → поздний результат возвращал загруженный рисунок. Для контроля использовано задержанное разрешение реального декодирования, а не фиктивный File.

Ожидаемые отрицательные результаты сохранены в игнорируемом `work/constructor-ux/{before,decode-before}-results.json`. Они не выдаются за успешную приёмку. Дополнительные Node-тесты проверяют whitelist/валидацию и ошибки хранилища; исходный ERR_MODULE_NOT_FOUND при подготовке нового модуля не считается доказательством поведенческого дефекта.

## Причины и исправления

### Мобильные вкладки

В DOM вкладки находятся **перед** `.builder` с превью. Прежние независимые sticky-offsets предполагали обратный визуальный порядок: tabs top292/z5, preview top120/z6. При входе через якорь ещё не закрепившееся превью перекрывало закреплённые вкладки. Дополнительная прокрутка лишь временно скрывала проявление ошибки.

В mobile media query ≤700 px порядок sticky согласован с DOM: **шапка → вкладки → превью → настройки**. Вкладки закрепляются на 120 px и выше по z-index, превью — на 173 px. Высота, ширина, оформление кнопок/альбома и существующий вариант компактного превью для низких экранов сохранены. Desktop media queries и порядок DOM не перестраивались. На пяти ширинах проверены hit-test, реальный клик по трём вкладкам, прокрутка, ввод надписи и добавление в корзину. Дополнительно проверены те же контролы с включённой анимацией на 390 touch и 1440 px.

### Автосохранение проекта

Раньше состояние находилось в `let state`, а ручные save/load существовали только за скрытой `.project-actions`. Новый `src/constructor-draft.js` хранит версионированный **whitelist метаданных**:

- модель и рисунок, оттенок дерева, цвет кожи, переплёт;
- текст гравировки и выбранные дополнения;
- scale, x/y, rotation, threshold, original/engrave;
- этап binding/cover/extras;
- только boolean `artworkRequired` для пользовательского рисунка.

Запись небольшого JSON выполняется синхронно после изменения состояния и этапа — immediate reload не зависит от debounce/таймера. При старте JSON проверяется по версии, типам, диапазонам и известным вариантам. Повреждённый/устаревший проект не применяется. Ошибки доступа/квоты не ломают конструктор, UI не обещает сохранение при неудачной записи.

Доступная кнопка **«Сбросить проект»** очищает только ключи незавершённого проекта и возвращает исходные настройки/первый этап. Корзина, избранное и Woo-сессия не очищаются. Небольшой статус и reset размещены в существующей панели; двухколоночная desktop-компоновка сохранена.

### Изображения и приватность

**Ни исходный File, ни уменьшенный PNG/data URL, ни сессионные токены не записываются новым механизмом в localStorage.** Для отображения и загрузки оригинал хранится только в памяти открытой страницы. Текст персонализации сохраняется согласно заданию; это не хранилище файлов.

После reload восстанавливаются параметры и признак собственного рисунка, но не байты изображения. Видны текстовое предупреждение и заглушка на обложке с просьбой загрузить оригинал. До повторной загрузки нельзя добавить позицию как обычный альбом без рисунка: проверены и demo-handler, и live configuration. Выбор готового рисунка либо полный reset явно снимают требование оригинала.

После повторной загрузки сохраняются ранее выбранные положение/масштаб/обработка, и в Woo отправляется **полный File**, как до исправления. Проверка идентичности original File в commerce-ui сохранена; 600px эскиз не используется как производственный оригинал. Обновлено пояснение загрузки: после обновления страницы нужен оригинал, без обещания «хранится только в браузере» для уже отправленного заказа.

Прежний `woodbase-project` мог содержать preview. При загрузке его метаданные мигрируют в `woodbase-draft-v1`, старый ключ удаляется. Чтобы выполнить запрет хранения приватных файлов и для существующей demo-корзины, её сохраняемый JSON также очищается от image/configuration.image и неизвестных полей. В памяти текущей страницы рисунок остаётся; после reload корзина сохраняет персонализацию и отметку «оригинал нужно приложить заново». Текст заявки учитывает эту отметку и не подменяет собственный рисунок готовым мотивом.

Счётчик ревизии отменяет поздний результат decode после нового выбора, удаления рисунка, импорта или reset. Очистка также убирает старый src скрытого thumbnail. Это предотвращает повторное появление сброшенного рисунка.

Исправлено чтение уже доступных метаданных при ошибке последующей записи: они восстанавливаются, но UI честно предупреждает о невозможности сохранять изменения. Основной браузерный регрессионный сценарий воспроизводится командой `npm run test:constructor:ux` при работающих локальных demo5174/live5173/WP8088. Он записывает screenshots/results, не публикует сайт и не создаёт коммерческие платежи. Закрытие браузера/очистка контекста не затрагивает чужие профили.

Normal-motion: [390 px touch](constructor-ux-assets/motion-390.jpg), [1440 px](constructor-ux-assets/motion-1440.jpg). Анимационный тест ожидает фактического завершения переходов/opacity=1, а не предполагает завершение через фиксированные 900 ms; промежуточные неудачные прогоны с фиксированной паузой не считаются PASS.

## Изменённые файлы

- `src/studio.css` — только мобильные sticky offsets/порядок слоёв и оформление статуса/reset в существующей палитре.
- `src/constructor-draft.js` — схема, безопасное чтение/запись/миграция и очистка сохраняемой demo-корзины.
- `src/main.js` — подключение автосохранения/восстановления/reset, сообщения о повторном оригинале, защита от позднего decode.
- `src/commerce.js` — запрет незаметной подмены восстановленного собственного рисунка обычной конфигурацией.
- `tests/constructor-draft.test.mjs`, `tests/commerce.test.mjs` — регрессии хранения/приватности/валидации.
- `scripts/verify-constructor-{ux,motion}.mjs`, `package.json` — повторяемые browser checks и команда запуска.
- Этот отчёт, сравнительные screenshots; сохранённые отчёт/скриншоты предыдущего аудита.

## Оставшиеся замечания и границы

- Повторная загрузка оригинала после reload обязательна намеренно. Файлы не восстанавливаются из browser storage; прикреплённый к уже созданной серверной корзине/заказу макет продолжает храниться на backend по прежней политике.
- Браузерное хранилище можно запретить/очистить; тогда UI предупреждает и нельзя гарантировать восстановление. Синхронизация одновременного редактирования в нескольких вкладках/между устройствами не добавлялась.
- Ручной legacy import/export проекта остаётся скрытым, как в исходном studio; основной пользовательский путь теперь автосохранение + reset.
- Остальные пункты аудита (пять неподключённых моделей, платежи/доставка, SEO, контрастность, контакты, производительность вступления и публичная HTTPS/backup-приёмка AdminVPS) этим исправлением не закрываются.
- Эмуляция Chromium не заменяет реальный iPhone/Safari/Android. Production, AdminVPS и Vercel не менялись; реальных платежей/доставки не было.
- Создаётся отдельный **локальный** коммит. Push, PR и merge не выполняются.
