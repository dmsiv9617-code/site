# Ozon: план проверки, а не подтверждение совместимости

2026-11-05. Запросы к https://docs.ozon.ru/ и https://woodev.ru/ возвращают CONNECT 403 сетевого фильтра среды; актуальная документация и дистрибутивы Ozon не получены. GitHub и локальная среда работают. Версии, поддержка HPOS, classic/Blocks, webhook-контракты и названия необходимых credentials НЕ подтверждены. Ни один плагин Ozon не установлен (сам WooCommerce и собственный WoodBase установлены локально). Ни реальных, ни тестовых транзакций/отправлений не создано.

## Ozon Pay

1. Получить официальный дистрибутив и документацию Ozon Pay для WooCommerce; проверить поставщика, версию, changelog, PHP/WP/WC требования, HPOS и явную поддержку classic/Checkout Blocks.
2. Проверить требования подключения юрлица/ИП, договор/мерчант, тестовый контур, разрешённые URL возврата и callback, HTTPS. Точный набор credential fields брать из действующей документации; хранить серверно, не VITE_* и не Git.
3. Подготовить staging checkout и тестовый каталог. Отключить реальные gateways и внешние отправки. Проверить оба checkout, гостя, успешный/отклонённый/отменённый платёж, timeout и повторный переход.
4. Проверить документированную аутентификацию webhook, соответствие суммы/валюты/merchant/order, идемпотентность и порядок событий, поддельные callback и повторную доставку. Возврат в браузер не доказывает оплату.
5. Согласовать статусы WC по документации; не обещать конкретное mapping до проверки. Проверить полные/частичные возвраты, повтор webhook и сверку состояния с провайдером.
6. Уточнить ответственность за онлайн-кассу/фискализацию, чеки прихода/возврата, НДС и состав позиций; не считать, что платёжный плагин автоматически закрывает эти требования.

## WooDev Ozon Доставка

1. Получить актуальную документацию/лицензионные условия WooDev, changelog и требования WP/WC/PHP; платную лицензию не покупать без отдельного согласования.
2. Подтвердить тип интеграции и необходимые доступы по документации. Не путать Ozon Marketplace seller API с самостоятельной доставкой интернет-магазина.
3. Проверить поддерживаемые способы доставки, географию и ограничения, виджет выбора ПВЗ, сохранение ID/адреса ПВЗ в заказе и совместимость с обоими checkout/HPOS.
4. В тестовом контуре проверить тарифы/ошибки расчёта, габариты и массу упакованного альбома, недоступность ПВЗ, смену адреса и повторный пересчёт; браузерный тариф не считать окончательным без серверной проверки.
5. Проверить создание/отмену отправления, этикетки, уникальность shipment ID, повтор запросов, аутентификацию статусов, polling/webhooks и правила повторов согласно документации. Не отправлять запрос create-shipment в коммерческий контур.
6. Для изделия под заказ согласовать срок производства и момент создания отправления: оплата не означает готовность к отгрузке. Нужны подтверждение мастера, упаковочные характеристики, сроки хранения в ПВЗ и поддержка возвратов.

## Матрица допуска

Для каждого кандидата записать URL документации/дату, версии плагина/WP/WC/PHP, HPOS, classic guest checkout, Blocks guest checkout, payment failure/retry/refund, shipping PVZ/rate/status. Статус сейчас во всех строках: НЕ ПРОВЕРЕНО. Выбор checkout возможен только после этих проверок; неподдерживаемые комбинации документировать, не переписывать архитектуру автоматически.


## Результат локального сравнения checkout

Classic: гостевой заказ через UI успешно создан с ручным тестовым BACS и сохранением snapshot/макета в HPOS. Store API checkout (серверная часть Blocks): локальный BACS заказ создан HTTP 200. Отдельная страница Blocks показывает пустую корзину; её полный UI-путь и совместимость Ozon не подтверждены. Не переносить этот результат на платёжные/доставочные плагины. Для первой локальной демонстрации использовать classic, для production провести полную матрицу с официальными версиями плагинов.
