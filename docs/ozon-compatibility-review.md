# Ozon Pay / WooDev Ozon Доставка — проверяемая матрица

Дата: 5 ноября 2026. Контекст: WoodBase hardening, тестовый WP 6.8.3 / WooCommerce 10.3.5 / PHP 8.3.28, HPOS, classic checkout, гостевые заказы. Коммерческие аккаунты не подключались, лицензии не приобретались, реальные платежи/отправления не выполнялись. Сторонние сборки модулей не скачивались.

## Источники и ограничения

Повторные запросы к первичным сайтам `https://docs.ozon.ru/` и `https://woodev.ru/` 5 ноября завершились `CONNECT tunnel failed, response 403` от сетевого фильтра среды. Это не сообщение вендора о поддержке/неподдержке WooCommerce. Точные официальные страницы модулей, версии, дистрибутивы и changelog не получены. Предыдущий доступный GitHub-поиск также не дал проверяемого первичного источника; это не доказывает отсутствия плагина.

Статус **«не подтверждено»** означает отсутствие достаточного первичного подтверждения/теста, а не установленную несовместимость. Для **«подтверждено»** нужны: официальный URL, дата, точная версия модуля/WP/WC/PHP, выдержка о поддержке или воспроизводимый тест с официальным дистрибутивом.

## Что подтверждено без Ozon

Локальный гостевой classic checkout WoodBase с ручным BACS создаёт заказ с personalization snapshot, HPOS и приватным PNG. Защищённый download и server price проверены. Это доказательство своей интеграции/Woo, **не совместимости Ozon**. Seed SKU virtual для изоляции доставки; его нельзя передать в коммерческую доставку в таком состоянии.

## Порядок исследования после доступа к первичным источникам

1. Получить официальные requirements/release/changelog обоих модулей. Зафиксировать точные версии и поддержку classic/guest/HPOS. Проверить актуальную поддерживаемую базу WP/WC, а не автоматически переносить dev pins на production.
2. Уточнить договорные требования и схему sandbox. Набор merchant/API/webhook credentials брать из действующей документации; названия и обязательность полей здесь не выдумываются. Хранить только backend/secret store, не VITE_* и не Git.
3. Создать отдельный HTTPS staging с синтетическим физическим SKU. Измерить массу/габариты **упакованного** изделия, согласовать единицы Woo/plugin, вложения и количество; старые hardcoded 33×22 не являются shipping package dimensions. Не переносить все модели до одной принятой комбинации.
4. Для Pay: guest success/failure/cancel/timeout/retry, return URL не считать оплатой; проверить аутентичность callbacks, merchant/order/amount/currency, replay/out-of-order, double payment prevention, сверку статусов, полные/частичные возвраты и фискализацию по документации. Денежные операции — только разрешённый sandbox.
5. Для доставки: гостевой ПВЗ/адрес, недоступный ПВЗ, регион/ограничения, серверный тариф и повторный расчёт, сохранение ID/адреса ПВЗ в HPOS; этикетки/отмена/статусы/повтор create-shipment. Отправление создавать **после подтверждения готовности мастерской**, а не автоматически по факту оплаты. Никаких реальных отправлений.
6. Подтвердить URL callback и исключения cache/auth/rate на основании официального модуля. В шаблоне есть REST, `/wc-api` и `?wc-api`, но это не обещание точного контракта. Staging Basic gate требует узкого согласованного исключения для sandbox webhook с проверкой его подписи; не отключать всю защиту. Произвольные plugin PHP URL по умолчанию запрещены.
7. Заполнить матрицу результатами с логами без секретов/PII и тестовыми order IDs. Только после этого выбрать окончательный production checkout/gateway/shipping workflow и запрашивать отдельное коммерческое подключение.

**Итог:** матрица подготовлена, но совместимость модулей не подтверждена. Это открытый блокер коммерческого запуска; сетевой 403 не обходился сторонними прокси/непроверенными сборками.
