# Оформление заказа и передача в мессенджер

Статус: реализация для отдельной серверной установки. Не объявлять её работающей на VPS до установки и проверки. Регистрация покупателя и онлайн-оплата не добавляются.

## Сценарий

Корзина → «Оформить заказ» → один из двух способов:

- Оставить заказ: выбрать Telegram, VK или MAX и указать свой контакт. Создаётся гостевой заказ WooCommerce со статусом «Нужно связаться с покупателем».
- Написать в мессенджер: выбрать подключённый прямой чат, сохранить заказ, скопировать описание и перейти в чат. Контакт на сайте не требуется. Статус «Ожидает сообщения покупателя».

После сохранения показываются номер, описание всех позиций и рассчитанная сервером сумма. Покупатель подтверждает отправку сообщения самостоятельно. Короткое описание передаётся в Telegram через `text`; для длинного заказа, VK и MAX используется копирование. Никаких сообщений от имени покупателя сайт не отправляет. Пользовательские контакты не включаются в адрес перехода.

Корзина очищается после сохранения заказа. В текущей сессии браузера можно повторно открыть подтверждение после перезагрузки. Номер сам по себе не даёт доступа к заказу: восстановление требует исходной серверной сессии, nonce и непрогнозируемого идентификатора запроса. Это не постоянный личный кабинет; после истечения сессии нужно обратиться в мастерскую с номером.

## Состав и цены

Сохраняются все позиции, количество, материал, переплёт, рисунок, надпись, дополнения, производственный снимок и ссылки на оригиналы в существующем закрытом хранилище. Используются существующие hooks защиты файлов. Публичных ссылок на оригиналы нет.

Суммы берутся из WooCommerce после повторной проверки конфигурации. В запрос оформления цены не передаются. Доставка, оплата и окончательный макет согласуются отдельно; сумма в подтверждении — стоимость альбомов и дополнений. Купоны в новом сценарии пока не поддерживаются: такой заказ отклоняется без потери корзины.

Пакет включает ранее согласованный серверный расчёт дополнений: 350/120/295/120 ₽. Старый `docs/woocommerce-extras/server-pricing.patch` повторно применять не нужно — его изменения включены в плагин 0.3.0.

## Защита от повторов

Идентификатор попытки хранится в sessionStorage без контактов. Сервер связывает его с владельцем сессии. Повтор возвращает существующий заказ даже при пустой корзине. При обрыве сохранения продолжается тот же заказ. Блокировка владельца и дополнительная привязка к составу корзины предотвращают дубли из разных вкладок. Новый осознанный заказ получает новые идентификаторы добавленных позиций.

Обновления не заменяют базу и не требуют миграции схемы. Дополнительные данные записываются через WooCommerce CRUD, включая HPOS.

## Установка и включение

По AGENTS.md изменения `integrations/woocommerce` требуют отдельной проверки и ручной установки. Автопубликация блокируется штатной проверкой backend; fingerprint здесь не менялся.

1. Проверить diff, сделать резервную копию текущих файлов плагина и сверить версию на VPS. Не выполнять local bootstrap на VPS.
2. Установить согласованный комплект `woodbase.php`, `hardening.php`, `state.php`, `extras-pricing.php`, `order-checkout.php` в существующий плагин. Сохранить существующие настройки, базу и private volume. PHP-файлы должны быть доступны на чтение PHP-FPM (обычно права 0644); не открывать доступ к закрытым рисункам.
3. Проверить сценарий в staging. До включения функция не объявляется в API и сохраняется обычный checkout WooCommerce.
Настройки доступны в защищённой администрации: **WooCommerce → Оформление WoodBase**. Прямые ссылки и документы можно заполнить там, без редактирования кода.

4. Подготовить и опубликовать реальные документы: политика обработки данных и отдельный текст согласия для заказа. Их URL записать в опции `wb_order_privacy_url` и `wb_order_consent_url`. Зафиксировать даты/редакции в самих документах; заказ сохраняет URL, время и версию формата согласия. Подтверждение в checkbox не заменяет выполнение юридических обязанностей продавца.
5. Опция `wb_messenger_contacts` — ассоциативный массив только проверенных прямых адресов: `telegram` → `https://t.me/...`, `vk` → `https://vk.me/...`, `max` → `https://max.ru/...`. Ссылку на группу `https://vk.ru/woodbase` не подменять прямым чатом без проверки. Отсутствующие каналы не отображаются в варианте самостоятельной отправки. Для обратной связи покупатель может указать свой контакт в любом из трёх мессенджеров.
6. Проверить адрес получателя и включение письма «Новый заказ» в WooCommerce, SMTP/доставляемость. Уведомление использует существующий WooCommerce mailer; сбой почты не отменяет сохранённый заказ. Заказы всегда доступны в административном списке. Автоматические уведомления в чаты мастерской не подключены.
7. После готовности установить `wb_order_checkout_enabled` в true. Проверить `/product`: `orderCheckout.version` равен 1. Если документы не заданы или опция выключена, новый сценарий не включается.
8. По существующей процедуре `docs/github-vps-updates.md` согласовать backend и витрину; не обходить fingerprint. Проверить две ветки, оригинал рисунка, повтор запроса, сумму, уведомление и мобильный интерфейс на VPS.

Не включать оплату и не менять действующие ручные способы оплаты в рамках этой установки. Для отката сначала отключить флаг; сохранять возможность обслуживать новые статусы и читать дополнения в уже созданных заказах.

## Проверки

- `npm test`, `VITE_COMMERCE_MODE=woocommerce npm run build`.
- `python3 scripts/verify-order-checkout-server.py`: только локальный Compose, реальные WooCommerce/HPOS и хранилище файлов.
- `node scripts/verify-order-checkout.mjs`: локальная WooCommerce-витрина на 5173; две ветки, потерянный ответ, повтор, восстановление и изоляция сессий. Тест не открывает внешние чаты и не создаёт заказы на VPS.

Локальные тестовые ссылки документов и `woodbase_test` используются только тестом. Они не являются контактами WoodBase и не публикуются в конфигурации VPS.
